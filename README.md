# Cogniflux

Локальный веб-чат с ИИ на базе **LM Studio** (OpenAI-compatible API).
Бэкенд — Python (Flask), фронтенд — HTML/CSS и чистый JavaScript (ES-модули).
Библиотеки подключаются с CDN: marked (Markdown), DOMPurify (очистка HTML), highlight.js (подсветка кода), шрифт Inter.

## Установка и запуск

1. Установите Python 3.10+, Node.js (нужен только для запуска JavaScript-кода модели) и LM Studio.
2. В LM Studio загрузите модель и включите локальный сервер (вкладка Developer / Local Server, порт 1234).
3. В папке проекта:

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate    macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
python app.py
```

4. Откройте в браузере **http://127.0.0.1:8080**.
5. В настройках → **Подключение** нажмите «Проверить подключение» и выберите модель.

Если порт 8080 занят, `app.py` выведет сообщение. Измените `"port"` в `config.json` (скопируйте `config.example.json`) и запустите снова.

Зависимости: `flask`, `requests` (сервер), `pypdf` и `python-docx` (извлечение текста из PDF и DOCX).

## Адрес LM Studio

- По умолчанию: `http://localhost:1234/v1` (значение `default_base_url` в `config.json`).
- Меняется в настройках приложения: Настройки → Подключение → Base URL.
- API key нужен только если в LM Studio включена авторизация.

Запросы идут через локальный сервер Cogniflux (`/api/models`, `/api/chat`), поэтому CORS в LM Studio настраивать не нужно. Ключ передаётся серверу только на время запроса и не записывается на диск. В браузере он хранится в IndexedDB, поэтому на общем компьютере лучше оставить поле пустым.

## Размышление, функции и выполнение кода

Под полем ввода три переключателя:

- **Размышление** — к системному промпту добавляется просьба рассуждать пошагово внутри тегов `<think>…</think>`. Ход рассуждений показывается в свёрнутом блоке «Ход рассуждений» над ответом. Это не встроенный режим модели: качество зависит от модели, а модель может проигнорировать просьбу.
- **Функции** — модели доступны инструменты для файлов. У каждого чата своя рабочая папка `workspace/<id чата>/`, создаётся при первом обращении; относительные пути считаются от неё:
  - чтение файла и список файлов — выполняются сразу;
  - отправка файла (`send_file`) — выполняется сразу, в чате появляется ссылка на скачивание;
  - запись файла — выполняется сразу, без подтверждения.
- **Выполнение кода** — модель может запускать Python, JavaScript (Node.js) и bash в рабочей папке чата сразу, без подтверждения.
- **HTML-панель** (`show_html`) — модель показывает в ответе HTML/CSS/JS-панель (дерево, схему, график). Панель работает во фрейме с `sandbox`, без доступа к приложению и к данным чата.

Инструменты отдельно включаются и выключаются в Настройки → Инструменты. **Подтверждения отключены**: модель может записывать файлы и запускать код в рабочей папке чата без вашего разрешения. Веб-поиск не поддерживается.

Ограничения выполнения кода: время до 20 секунд, размер создаваемых файлов до 50 МБ, для Python — память до 1 ГБ, размер вывода до 12 000 символов. Лимит последовательных вызовов инструментов в одном ответе — 6.

**Это не песочница.** Код выполняется от вашего имени и может читать и менять любые файлы, до которых у вашей учётной записи есть доступ, включая файлы вне `workspace/`. Подтверждайте только тот код, который понимаете. Сервер слушает только `127.0.0.1`, и не открывайте его в сеть.

## Где что хранится

- Чаты, папки, вкладки и настройки — в IndexedDB вашего браузера (база `cogniflux`).
- Файлы, которые создала модель через инструменты, — в папке `workspace/<id чата>/` на диске компьютера, где запущен `app.py`. Папка видна в панели информации чата. Удаление чата папку не трогает.
- Ничего не отправляется в облако. Внешний адрес — только ваш LM Studio.
- Экспорт/импорт истории: Настройки → Данные и приватность (JSON).
- Полное удаление: там же, кнопка «Удалить все локальные данные» (файлы в `workspace/` при этом остаются).

Фронтенд — три модуля без сборщика: редактируйте файлы и обновляйте страницу.

## Скилы

Скил — набор инструкций для особой задачи. Под полем ввода переключатель **Скилы**:

- В системный промпт попадает каталог «имя — когда применять». Если задача подходит, модель вызывает `load_skill` и получает полный текст инструкций.
- Скил можно вызвать явно: `/имя` в начале сообщения.
- Встроенные скилы: `code-review` (ревью кода), `document-summary` (краткое изложение), `explain-simply` (объяснение простыми словами). Их можно выключить в Настройки → Скилы.
- **Создать скил** — режим, в котором модель уточняет задачу и сохраняет новый скил инструментом `create_skill`. Пользовательские скилы хранятся в IndexedDB браузера, их можно выгрузить в `.md` или удалить.

Скилы `load_skill` и `create_skill` выполняются в браузере, сервер их не запускает.

## Веб-разработка

Режим **Веб-разработка**: модель пишет одну HTML-страницу (CSS и JavaScript внутри файла) и показывает её в предпросмотре по мере написания. Особенности:

- Лимит токенов ответа не передаётся, поэтому длина ограничена только моделью и контекстом LM Studio. Если ответ оборвался по длине, Cogniflux продолжает его сам (до 8 раз подряд).
- Предпросмотр работает в песочнице с запретом сети и без `localStorage`. Страница скачивается кнопкой «Скачать .html».
- В режиме веб-разработки инструменты отключены, режимы «Создать скил» и «Веб-разработка» взаимно исключают друг друга.
- Чтобы повлиять на результат, пишите правки в чат: модель вернёт полный обновлённый файл.

Проверено сквозным тестом в Chromium с подменённым ответом сервера: предпросмотр появляется до конца ответа, автопродолжение склеивает страницу без дублей. Работу с настоящей моделью не проверяли.

## Тесты

```bash
python -m unittest discover -s tests -v
```

Тесты проверяют валидацию запросов, границы папки workspace, запись и чтение файлов, запуск Python-кода и таймаут. Работу с реальной моделью они не проверяют.

## Возможности

- Несколько независимых чатов; каждый запрос привязан к своему чату, поэтому ответ не попадёт в другой диалог.
- Вкладки: закрытие вкладки не удаляет чат; недавно закрытые можно открыть из меню.
- Потоковый вывод токенов, кнопка «Стоп» (AbortController), повтор после ошибки, продолжение остановленного ответа, перегенерация.
- Редактирование своего сообщения: ответы после него удаляются, ветки не смешиваются.
- Чаты: переименование, закрепление, дублирование, архив, перенос в папку, удаление с подтверждением.
- Папки: создание, переименование, удаление (чаты при этом сохраняются и переходят в список без папки).
- Поиск по названиям и по тексту сообщений.
- Markdown, таблицы, блоки кода с подсветкой и кнопкой копирования, копирование сообщений.
- Вложения: текстовые файлы, PDF и DOCX (текст извлекается на сервере), изображения (PNG, JPEG, WebP).
- Параметры генерации: temperature, top_p, max_tokens, frequency/presence penalty, seed. Передаются только заданные значения.
- Размышление, функции (файлы в workspace) и выполнение кода (Python, JavaScript, bash) с подтверждением.
- Светлая, тёмная и системная темы; русский и английский интерфейс (английский — не полностью).
- Экспорт чата в Markdown, экспорт и импорт всей истории в JSON.

## Что пока не работает (и это сказано честно)

- **PDF без текстового слоя** (сканы) не распознаются: OCR не подключён.
- **Веб-поиск** не поддерживается намеренно.
- **Параметры по чатам** — сейчас параметры общие для всех чатов.
- **Размышление** — промптовое, а не встроенное: модель может не следовать просьбе.
- **Вызов инструментов** зависит от модели и версии LM Studio. Если модель не поддерживает инструменты, сервер вернёт ошибку, и интерфейс подскажет отключить «Функции» и «Выполнение кода».
- **Сервер** — стандартный сервер Flask для локального использования, без авторизации.
- Размер контекста модели через OpenAI-совместимый API не передаётся, поэтому в панели он не показывается.

## Что проверено

- Синтаксис Python и JavaScript; серверные тесты в `tests/` (26 тестов, включая инструменты).
- Сценарии с реальным LM Studio (потоковая генерация, Stop, размышление, вызовы инструментов, подтверждение, проверка подключения) — **нужно проверить на вашей машине**: в среде сборки LM Studio недоступен.

## Безопасность локального API

- Запросы к `/api/*` принимаются только с адресов этого компьютера (`127.0.0.1`, `localhost`, `::1`). Это защищает от DNS rebinding.
- Заголовок `Origin`, если есть, тоже должен быть локальным.
- Изменяющие запросы (`POST`, `DELETE`) обязаны содержать заголовок `X-Cogniflux: 1`. Браузер не отправит его с чужой страницы без предварительного запроса, на который сервер не отвечает.
- HTML-панели (`show_html`) выводятся с политикой `Content-Security-Policy`: сеть из панели запрещена, разрешены скрипты и стили из `https:` и встроенные.
- Запуск кода: лимиты времени, памяти и размера файлов задаются внутри процесса (Python) или через `ulimit` (bash). При таймауте останавливается вся группа процессов. Подтверждения отключены, поэтому код выполняется сразу. Это по-прежнему не песочница.

## Контекст

- Перед отправкой история обрезается по лимиту «Лимит контекста, символов» (Настройки → Генерация, по умолчанию 48 000). Всегда сохраняется последнее сообщение, а диалог начинается с сообщения пользователя. В панели информации видно, сколько ранних сообщений не передано.

## Удаление чата

- Удаление чата удаляет и его рабочую папку на диске вместе с файлами.
